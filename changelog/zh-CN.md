# 更新日志

重要变更按时间倒序排列。当“Unreleased”部分为空时，Deploy 流水线会拒绝发布，并在发布时为该部分标注发布的版本号。

## Unreleased

- 设置 > 关于中的更新日志现在会列出已安装版本的更新说明；在 v1.0.11 中，无论是桌面应用还是远程网页，更新日志都仍停留在 v1.0.10。

- 更新日志现已提供所有应用语言的版本，更新后应用会就该版本的新内容提示一次。

- 在受支持的模型上，自动推理默认开启：每条消息和每个工具步骤都会获得其所需的推理强度。其模型改为首次使用时在后台下载，而不是在启动时下载，内置卡片会显示该模型及其所基于的模型。

- 对话中的文件链接会以标签页的形式在侧边面板中于对话旁打开。新链接会替换预览标签页，因此链接不会再堆积出大量标签页；双击标签页、选择保持打开或编辑文件后，该标签页会被保留。最多同时保持打开八个文件标签页。可在设置 > 常规 > 链接预览中关闭此功能。

- CSV 和 TSV 文件可作为可编辑的表格打开：可复制粘贴单元格、添加或删除行和列，用 Ctrl+S 保存，用 Ctrl+Z 和 Ctrl+Y 撤销或重做。

- PDF 和 Office 文件（Word、PowerPoint、Excel）可在侧边面板中预览。Office 页面可立即重新打开，当你将鼠标指向链接时，就会开始转换其文档。

- 对话可以加星标：收藏的对话会固定在会话列表顶部，将鼠标悬停在某一行上时会显示星标。

- 搜索可在过往对话中查找文本。无论以何种方式删除，已删除的对话都不会留下任何搜索结果。

- 回复流式输出时向上滚动，会保持你当前的位置，而不是跳回底部。

- 回复中的 GitHub 操作会归并到一张 GitHub 卡片中，思考指示器的循环动画在重新开始时也不再跳动。

- 提供商账户会显示其登录邮箱；再次连接同一账户时，会保留其名称和使用历史，而不是新增一条记录。用量对话框不再列出已断开连接的账户。

- 从队列中撤回到草稿的提示词，重启后不再重新出现；快速重新打开应用时，对话会保持可编辑，而不是以只读方式打开。

- 翻译修正：意大利语中的 Git、越南语中的 Models、中文和日语中的 Effort 等错误标签，现在都能正确显示。

- 在手机网页界面中，Enter 键插入换行，发送按钮负责发送。

- 在用户文件夹名称不是纯 ASCII 的 Windows 用户配置文件上，记忆现在可以正常启动。

- image-size 和 js-yaml 依赖的安全更新（CVE-2025-71329、CVE-2026-84375）。

## v1.0.11 - 2026-10-08

- 内置浏览器在缩放比例高于 100% 的 Windows 显示器上可以再次正常显示页面，不再报错“Browser display did not recover after the page changed”（#8）。页面也会跟随显示缩放比例的变化，包括当时不在屏幕上的标签页。

- Word、PowerPoint 和 Excel 文件（.docx、.pptx、.xlsx、.xlsm）可以附加到消息和自动化中，其文本会传递给所有模型。无法附加的文件类型现在会给出提示并改为插入文件路径；空文件或并非真正 PDF 的文件会被拒绝，并给出明确的提示。

- 对话中较早的 PDF 和图片在应用重启后仍会发送给模型。不支持原生 PDF 的模型会收到 PDF 的文本。读取超过 100 页的 PDF 时会以文本形式返回前几页；受密码保护或无效的 PDF 会返回明确的错误，而不再导致之后的请求出错。

- MCP 工具返回的图片和文件现在会以图片和文件的形式传给模型，而不是原始编码文本；不支持或过大的媒体会被说明。

- 长对话压缩时生成的摘要现在包含较长的消息，并会注明附加的图片和文件。

- 仅支持文本的本地模型会保留所附文档的文本，较早的图片则变为简短说明，而不会中断对话。

- 可以在设置 > 关于中发送反馈（可附截图），也可以在那里阅读更新日志。

- 在记忆召回中，最近的对话消息保存后即可按语义被找到。

- 搜索结果仅在仍然有效时才会被复用（#7）；内容搜索之后进行的文件列表搜索会返回文件名，而不是之前的内容（#9）。

## v1.0.10 - 2026-10-08

- 可以在设置中注册自定义 API 提供商，并使用特定于提供商的连接适配器。

- 远程连接二维码仅在中继就绪后才会显示，过期的配对卡片会被清除。

- 可以为主要模型和代理选择并保存 OpenRouter 滚动模型别名。最新别名和稳定模型不再因目录时间、较新的预览版或模型选择器的系列限制而被错误隐藏。

- 原生补丁初始化在验证尚未完成期间会保持其进程存活，避免预热与验证重叠时提前退出。

## v1.0.9 - 2026-10-07

- 即使未安装记忆扩展或已将其关闭，通用指令和项目指令也会传递到每个新对话；该开关现在只控制记忆和召回工具。保存指令时不再需要等待嵌入模型数秒，指令会按原文写入、不带内部 id，总量最多可达 32 KB。

- 在已安装的桌面应用中，从设置登录 GitHub 以及其他所有需要启动终端进程的功能都已恢复正常，不再报错“posix_spawnp failed”。gh 保存的过期额外 GitHub 账户也不再导致登录成功后仍提示“no account is signed in”。

- 浏览器使用和计算机使用在会话中首次调用前不再请求批准，`setup set_first_use_approval` 已移除。

- 工具批准卡片与输入框上方堆叠的卡片保持一致：警告图标、标题和工具位于同一行，原因显示在其下方且仅列出待批准的命令、路径或 URL（不再有文件夹行或参数转储），拒绝按钮则低调地置于允许按钮旁边。

- 新模型的能力现在直接取自提供商目录，无需等待新版本发布：ChatGPT 路线上的对话中途调整强度、OpenAI API 路线上的 Fast 模式和缓存设置、Claude 上的 Fast 模式，以及 xAI 上的推理强度。现已支持 GPT-6.1 Sol 和 Claude Sonnet 5.5，并且 Fast 开关不再出现在无法使用它的 Claude 模型上。

- Claude Sonnet 5.5 再次在工具调用之间显示其备注，Claude Fable 和 Mythos 模型可以使用托管的网页搜索。

- 每个提供商所期望的客户端版本会在多次运行之间被记住，因此重启或离线启动不再回退到过时的内置值。

- 来自 GLM、Kimi、Qwen、MiniMax、xAI 及其他后端的更多“对话过长”错误现在会触发压缩，而不是结束本轮；Claude 在回复中途过载时，也遵循与回复开始时过载相同的重试和回退规则。

- 通知和错误不再堆叠在输入框上方：斜杠命令确认以及麦克风、附件和命令失败都以通知形式出现，语音下载进度仅显示在其设置卡片上。所有错误现在的呈现方式一致，不再使用带边框的卡片，本地模型下载则在其所在行下方显示全宽进度条。

## v1.0.7 - 2026-10-04

- 手机上的浏览器使用现在会实时传输桌面页面，而不是刷新快照，并支持与桌面窗格相同的鼠标、触摸、滚轮、键盘和输入法输入。当代理交还页面时（例如遇到验证码），手机也会打开该页面。

- 对话记录中的工具活动更易于浏览：每一行以简短的动词开头，读取和搜索会显示逐文件的结果，列表显示文件行，命令位于独立的框中，`git diff` 输出以差异视图渲染，浏览器访问过的页面会生成一张卡片，可在窗格中重新打开。

- 应用界面保持 100% 缩放，在其他窗口或终端中保存的设置会立即生效，边框、图标、列表间距和对话框入场效果也更加一致。

## v1.0.4 - 2026-10-01

- 模型选择器会在提供商发生变化时立即刷新。基于浏览器的 OAuth 登录（OpenAI、Grok、Cursor、Antigravity）和账户切换现在会立即重新加载选择器，而无需重启；在某个窗口中连接、移除或切换提供商，也会刷新所有其他桌面窗口和已配对的手机。

- Goal 工具和 goal-management 技能将目标描述为跨多轮对话进行的已批准工作的任务列表，并排除了周期性计划以及需要等待数周外部事件的目标。

## v1.0.3 - 2026-10-01

- 媒体生成会为每个图片或视频任务记录一行用量，包含提供商报告的令牌数、图片数、秒数和费用，因此 Gemini、Antigravity、Codex 和 xAI 的媒体会与文本模型一同计入用量和费用合计。媒体费率来自已发布的价格目录。

- 计算机使用的停止和继续在清理失败后可以干净地恢复：空闲的 worker 会被回收而不是超时，用户的停止或继续操作会清除过期的“input not confirmed released”状态。

- 正在等待后台 shell 任务的会话显示为等待中而非空闲，shell 任务指示器不再显示上一个所有者的任务，也不再丢失轮询期间到达的更新。当没有变化时，会话和代理列表会跳过多余的重绘。用量图表、侧栏页面、工作区标签页、扩展列表和对话框采用了全新的样式。

- 相同的并发 grep 和 read 扫描共享一次原生扫描，编辑后缓存结果按路径失效，被取消的补丁会在写入更多文件之前停止。代码图搜索匹配 Windows 路径时不区分大小写、分隔符、verbatim（`\\?\`）和 UNC 前缀。失败的工具前置钩子现在会阻止该工具运行，而不是放任其执行。

- 浏览器技能会让页面保持在后台，除非页面本身就是交付物或需要用户亲自操作。桌面开发（`npm run dev`）和 Windows 直接 E2E 脚本在全新的隔离配置文件中运行，使用 CDP 端口 `9342`。

## v1.0.0 - 2026-09-30

- 记忆不会再因运行时重建而失效。重建后的记忆运行时会以新的发布标签发布，而不是替换已安装应用所校验的文件；新的运行时会安装在正在使用的运行时旁边，而不是在 PostgreSQL 仍从中运行时将其删除；两个进程同时安装时也不再互相删除对方的下载。本地开发部署会拒绝在落后于其上游的分支上运行。

- 工具卡片不再把已完成的调用标记为失败。输出中包含 `status:` 行的命令、报告有差异或无匹配的 `git diff --quiet` 或 `git grep`、未找到符号的 code_graph 查询，以及翻页查看已存储的 tidy 结果，现在都显示为已完成；以非零状态退出的 git 命令与 shell 一样显示为退出；因用户接管而停止的浏览器或计算机命令显示为已取消。

- 因首次尝试时参数失误而失败的工具调用更少了：git 工具会补上缺失的开头 `git`，read 在其 schema 中声明 10 个目标的上限，装满已完成任务的 Goal 会说明如何为新任务腾出空间。失败日志现在会记录 read 的目标以及路径批次的完整大小。

- 请求按其实际发送时所用的档位计价：Fast 和 Priority 请求使用其公布的费率，以标准档重试的 Fast 请求按标准计费，Cursor 的 Fast 变体按其目录中的模型计费。切换 Fast 会立即更新状态栏。

- 在创建工作簿之前会检查 Excel 数据验证规则，因此未知的规则类型或缺失的边界值会在两个后端上都提前失败。实时活动的光泽效果变为更短、更淡的光带，工具摘要名称使用中等字重。

## v0.9.175 - 2026-09-29

- Claude 代理现在将其对话缓存保留 5 分钟，而不是一小时。当代理的下一次请求在缓存过期之后到来时（例如长时间的构建或测试之后，或重新启用已完成的代理时），它会先压缩其对话，这样请求重写的是压缩后的对话，而不是代理累积的全部内容。在对近期 Claude 代理用量的回放中，这使代理的令牌成本降低了约四分之一。Lead 会话不受影响。

- 多个会话并行运行时不再互相拖慢。待处理消息按会话保存，会话摘要和网关用量改为追加而不是重写，已存储的对话记录在主循环之外解析，失败的记忆周期会退避而不是紧凑地循环重试。守护进程退出时会记录原因。独立的多进程会话宿主已移除，会话直接在守护进程内运行。

- 账户切换之前记录的订阅用量现在会计入开始记录时正在使用的账户。Grok、Claude 和 Cursor 会报告其当前的客户端版本，而不是固定版本。

## v0.9.172 - 2026-09-21

- 页面打开时不再通报它从未发起的下载。保存的文件属于会话，但每个页面都从零开始跟踪自己已报告的内容，因此之后打开的每个页面都会向调用者通报全部积压——比如搜索页面报告了几分钟前另一个标签页保存的文件。新页面现在一开始就知晓它出现之前发生的事；页面打开期间保存的文件仍会送达它。

- 浏览器自身的故障不再被当成页面的故障。超时的 CDP 调用、无法附加的子框架、无法应答的拦截——这些过去都被记录为页面控制台错误，因此关于一个正常站点的回复可能以 `CDP Runtime.evaluate timed out` 开头，仿佛是该站点记录的。它们仍可通过 `console` 查看，并标记为 `[browser]`，不再计入页面应负责的错误。

- 客户端路由变化现在会以其产生的画面作答，而不是调用者离开的那一个。单页应用用 `history.pushState` 改变地址，稍后才渲染新视图；没有文档加载，因此等待稳定的逻辑看到的是安静的页面并立即返回——而 `expect.url` 在任何内容绘制之前就被新地址满足了。在 react.dev 上点击“Learn”，得到的是 `/learn` 地址下的首页。当某个操作改变地址而没有加载时，回复现在会等待页面安静下来，URL 条件也不能使其提前结束。在真实设备测试平台上的测量：navigate、click 和 snapshot 的延迟不变，因为只有同文档的路由变化才会额外等待。

- WebSocket 详情现在显示它实际发送的升级请求。此前只记录了地址和握手响应，因此 `network` 返回的请求头部分为空——而被拒绝的升级通常可以用 `Origin`、`Sec-WebSocket-Protocol` 或 cookie 来解释。凭据仍然保持脱敏。

- 打开了标签页的点击不再被报告为什么都没做的点击。`target="_blank"` 链接不会改动当前文档，因此回复曾回答“No observable change”并让调用者去找遮挡元素——而它刚刚打开的页面就在 `list_tabs` 里，却未被提及。回复现在会指明打开的页面以及如何对其操作。

- `drag` 像其他所有指针操作一样支持无需快照的目标。它的两端过去只接受 ref 或原始坐标，而页面中可拖动的元素——卡片、列表行、放置区——往往没有可访问名称，因此也没有 ref，所以即使已知 CSS 选择器，移动一个元素也得先对视觉快照进行定位。现在 `target` 和 `dropTarget` 用来指明两端，并在一次观察中一起解析；ref 和坐标的用法与之前相同，两端仍必须用相同的方式寻址。

- 保存的文件不再被通报为失败的请求。变成下载的地址会取消自身的导航，Chromium 将该取消报告为 `net::ERR_ABORTED`，因此列出了该下载的回复也把它列为近期的网络故障。被取消的请求——下载、页面放弃的 fetch、被另一个导航取代的导航——仍可通过 `network` 查看，但不再被主动当作页面的故障报告；真正失败的请求仍会如此。

- 浏览器使用的域名策略涵盖对等连接。当运营者限制页面可以访问的域名时，WebRTC 不再通过 STUN 和 TURN 绕过过滤：页面及每个子框架中的对等连接都会被拒绝。没有域名策略时没有任何变化，而且这仍然是对页面代码的约束，而非网络边界。

- 浏览器使用的元素截图。`snapshot mode=visual` 接受 `ref` 或 `target`，并将该元素作为独立图像返回。边框以顶层文档的 CSS 像素测量——同进程框架在页面一侧折算其偏移，跨源框架加上其会话偏移，但不进行保护输入的命中测试，因为图片不派发任何事件，而处于 CSS 变换下的框架同样值得一张图片——并且裁剪按图像与视口之比缩放，因此在缩放或高 DPI 显示器上同样成立。比窗口更高或更宽的元素会从文档捕获而非视口中裁出，因此长表格或文章会完整呈现，而不是止于折叠线；只有过大而无法捕获的页面才会退回到可见部分，并会如实说明。该图像仅供检查：它绝不会被绑定为坐标定位，因为对元素执行操作仍应使用 ref。`mode=semantic`、`fullPage` 和 `format=pdf` 会拒绝 target，而不是忽略它。

- 浏览器使用的输入保真度。`drag` 现在可以完成页面自己的 HTML5 拖放：Chromium 的拖动拦截会交出页面发起的载荷，手势以 `dragEnter`/`dragOver`/`drop` 结束，这正是看板卡片、可排序列表或文件放置区实际监听的事件；只跟踪鼠标事件的页面保持之前的路径。`type` 为每个字符发送真实的按键事件，而不是插入整个字符串，因此由按键驱动的自动补全和组合框会有所反应，而美式键盘布局之外的字符（韩文、emoji）仍以文本插入。`press` 为标点发送美式键码（`.` 过去是 Delete，`-` 过去是 Insert），避免快捷键输入字符，并且不再根据大写字母推断 Shift，这曾把 `Control+A` 变成 `Control+Shift+A`。`upload` 可将文件放到从不打开文件选择器的元素上，并带有一个中和未处理放置的保护——否则浏览器会把页面导航到被放置的文件——在没有任何东西接受时会直接说明。

- 浏览器使用的观察保真度。`scroll text=` 像 `read` 和 `expect` 一样搜索框架和 shadow root，在它们之间选定一个匹配，并且不再滚动到已折叠的元素。`expect.text` 在行内规范化空格但保留换行，因此带缩进的标记可以匹配，而两个独立的块绝不会合并成一句话。控制台诊断会保留页面记录的内容：对象参数以可读的预览到达而不是空消息，条目会指明读者会打开的脚本和行号，未捕获的裸 `throw` 带有其位置。快照会标记 `aria-hidden`，失败的原生 `select` 会列出它确实找到的选项，`aria-labelledby` 可在 shadow root 内解析。

- 浏览器使用会统计它放不下的诊断信息。页面报告显示最新的三条控制台错误和网络失败，读起来就像事情的全部：十二个失败只显示为三个。每当列表被截断，报告现在会指出总数，并指向 `console` 或 `network`。

- 浏览器使用会承认页面摘录提前结束。快照中的可见文本有上限，而报告只说“condensed”，因此长文章读起来仿佛摘录就是整个页面。两条快照路径——无障碍捕获和 DOM 回退——现在都会标记被截断的摘录，并且报告会指明它包含多少内容，并说明页面还有更多。

- 附件报告的是它们实际生成的图像尺寸。把图像调整到视觉补丁预算时会逐条裁剪边缘，这可能要求一个图片并未铺满的框；于是生成的版本比旁边报告的尺寸更小，通过该尺寸映射的坐标也就偏了。现在调整大小会报告生成图像的尺寸。

- 浏览器使用会说明页面脚本在哪里失败。`evaluate` 只保留浏览器错误的第一行，因此多行脚本只报告 `TypeError: ...`，没有任何东西可用来定位。现在失败会携带最内层的堆栈帧，集成测试平台会固定住后面某行 throw 所报告的位置。

- 浏览器使用会指明 PDF，而不是报告一个空页面。打开 PDF 链接会提交地址，但 guest 没有查看它的查看器，因此快照显示的是没有标题、没有文本的页面，以及关于被阻止的查看器样式表的控制台噪音——没有任何东西说明发生了什么。页面报告现在会说明该文档是此浏览器无法显示的 PDF，需要从其 URL 读取文件，并且 Chromium 自带组件为其 `chrome-extension://` 资源引发的失败不再显示为页面的控制台或网络错误。集成测试平台涵盖了导航、安静的报告，以及之后对该页面的快照。

- 浏览器使用不再让 `close_tab` 被可见标签页弹回。`list_tabs` 以普通页面 id 打印可见页面，因此用 `close_tab` 指向它时得到的是 `unknown background tab "p12"; call list_tabs`——而发出该 id 的正是这个列表。现在拒绝信息会说明该页面属于浏览器面板，并建议将其导航到别处或使用 `hide`，不相关的名称仍会报告未知的后台标签页。

- 浏览器使用会说明离开确认实际做了什么。保护未保存工作的页面会用 `beforeunload` 对话框阻止导航，回复要求使用 `handle_dialog`——但 Chromium 自己应答该确认，所以调用总是返回“no JavaScript dialog is currently open”，而重复导航又重复同样的指示。现在回复会说明导航已被放弃、页面保持原状、已没有什么可应答的，而页面中保存的工作必须先完成或丢弃；集成测试平台涵盖了整个流程，包括保护消失后导航顺利通过。

- 浏览器使用的区域设置模拟会到达服务器。`emulate locale` 过去只设置 `navigator.language`，因此页面仍在请求旧语言，站点协商出的内容与模拟相矛盾；现在它也会把区域设置作为 `Accept-Language` 携带，清除它则会恢复浏览器自己的协商。
