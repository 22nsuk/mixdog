# 更新日誌

重要變更，由新到舊排列。Deploy 流程在 Unreleased 區段為空時會拒絕發佈，並在發佈時為該區段標上發佈版本。

## Unreleased

- 「設定」>「關於」中的更新日誌會列出已安裝版本的說明；在 v1.0.11 中，桌面應用程式與遠端網頁的更新日誌都仍只到 v1.0.10 為止。

- 更新日誌提供每種應用程式語言的版本，而且更新後，應用程式會顯示該版本的新內容一次。

- 在支援的模型上，自動推理預設開啟：每則訊息與每個工具步驟都會取得所需的推理強度。其模型會在首次使用時於背景下載，而不是在啟動時下載，且「內建」卡片會顯示該模型及其所基於的來源。

- 對話中的檔案連結會在旁邊的側邊面板以分頁開啟。新連結會取代預覽分頁，因此連結不再堆積分頁；雙擊分頁、選擇「保持開啟」或編輯檔案後，該分頁就會保留。最多同時開啟八個檔案分頁。「設定」>「一般」>「連結預覽」可關閉此功能。

- CSV 與 TSV 檔案會以可編輯的表格開啟：可複製與貼上儲存格、新增或移除列與欄、以 Ctrl+S 儲存，並以 Ctrl+Z 與 Ctrl+Y 復原或重做。

- PDF 與 Office 檔案（Word、PowerPoint、Excel）可在側邊面板預覽。Office 頁面會立即重新開啟，而且只要將游標指向連結，就會開始轉換其文件。

- 對話可以加上星號：我的最愛會固定在工作階段清單頂端，而游標移到該列上時會出現星號。

- 搜尋可在過去的對話中尋找文字。無論以何種方式刪除對話，都不會留下搜尋結果。

- 在回覆串流時向上捲動，會停留在目前位置，而不是跳回底部。

- 回覆中的 GitHub 動作會歸組為一張 GitHub 卡片，而思考指示器的循環動畫在重新開始時也不再跳動。

- 提供者帳號會顯示其登入電子郵件，而再次連接同一個帳號時，會保留其名稱與用量歷史，而不是新增一筆項目。用量對話框不再列出已中斷連線的帳號。

- 從佇列拉回草稿的提示在重新啟動後不再重新出現，而快速重新開啟應用程式時，對話仍可編輯，而不是以唯讀方式開啟。

- 翻譯修正：義大利文中的 Git、越南文中的 Models，以及中文與日文中的 Effort 等錯誤標籤，現在都能正確顯示。

- 在手機網頁 UI 上，Enter 會插入換行，而傳送按鈕才會送出。

- 在使用者資料夾名稱不是純 ASCII 的 Windows 設定檔上，記憶也能啟動。

- 針對 image-size 與 js-yaml 相依套件的安全性更新（CVE-2025-71329、CVE-2026-84375）。

## v1.0.11 - 2026-10-08

- 內建瀏覽器在縮放比例高於 100% 的 Windows 顯示器上又能正常顯示頁面，不再出現「Browser display did not recover after the page changed」的失敗（#8）。頁面也會跟隨顯示縮放比例的變更，包括當時不在畫面上的分頁。

- Word、PowerPoint 與 Excel 檔案（.docx、.pptx、.xlsx、.xlsm）可以附加到訊息與自動化中，其文字內容會傳達給每一個模型。無法附加的檔案類型現在會明確告知，並改為插入檔案路徑；空檔案或並非真正 PDF 的檔案則會被拒絕，並顯示清楚的訊息。

- 對話中先前的 PDF 與圖片在應用程式重新啟動後仍會傳送給模型。不原生支援 PDF 的模型會收到 PDF 的文字。讀取超過 100 頁的 PDF 時，會以文字形式回傳前幾頁；受密碼保護或無效的 PDF 會回傳清楚的錯誤，而不會導致後續請求失敗。

- MCP 工具回傳的圖片與檔案會以圖片和檔案的形式傳達給模型，而不是原始的編碼文字；不支援或過大的媒體則會以文字描述。

- 壓縮長對話時產生的摘要現在會包含較長的訊息，並註明附加的圖片與檔案。

- 僅支援文字的本機模型會保留附加文件的文字，先前的圖片則改為簡短註記，不再中斷對話。

- 可以在「設定」>「關於」傳送意見回饋（可附上截圖），也可以在該處閱讀更新日誌。

- 最近的對話訊息在儲存後，立即就能透過記憶回想依語意找到。

- 搜尋結果只在仍然新鮮時才會重複使用（#7）；在內容搜尋之後進行檔案清單搜尋，會回傳檔名，而不是先前的內容（#9）。

## v1.0.10 - 2026-10-08

- 可以在「設定」中註冊自訂 API 提供者，並搭配提供者專屬的連線轉接器。

- 遠端連線的 QR code 只會在中繼就緒後才出現，過期的配對卡片也會被清除。

- 可以為主要模型與代理選取並儲存 OpenRouter 滾動式模型別名。最新別名與穩定版模型不再因目錄項目的新舊程度、較新的預覽版或模型選擇器的系列數量限制而被錯誤隱藏。

- 原生修補程式初始化在驗證尚未完成時會保持其處理程序存活，避免預先暖機與驗證重疊時提前結束。

## v1.0.9 - 2026-10-07

- 即使未安裝記憶擴充功能或已將其關閉，通用指示與專案指示仍會傳達到每一個新對話；該開關現在僅控制記憶與回想工具。儲存指示時不再需要等待嵌入模型數秒，指示會依原文送出而不帶內部 ID，總量最多可達 32 KB。

- 從「設定」登入 GitHub，以及其他所有會啟動終端機處理程序的功能，在已安裝的桌面應用程式中又能正常運作，不再因「posix_spawnp failed」而失敗。gh 所儲存的過期額外 GitHub 帳號，也不再導致登入成功卻回報「no account is signed in」。

- 瀏覽器使用與電腦使用在工作階段中首次呼叫前不再要求核准，`setup set_first_use_approval` 也已移除。

- 工具核准卡片與輸入框上方堆疊的卡片一致：警告圖示、標題與工具位於同一行，理由顯示在其下方，且只列出要核准的命令、路徑或 URL（不再有資料夾列或引數傾印），而「拒絕」則低調地放在「允許」旁邊。

- 新模型會從提供者目錄取得其功能，不必等待新版本：ChatGPT 路線上對話中途變更強度、OpenAI API 路線上的 Fast mode 與快取設定、Claude 上的 Fast mode，以及 xAI 上的推理強度。現已支援 GPT-6.1 Sol 與 Claude Sonnet 5.5，且 Fast 切換開關不再出現在無法使用它的 Claude 模型上。

- Claude Sonnet 5.5 又會在工具呼叫之間顯示其註記，Claude Fable 與 Mythos 模型也可以使用代管的網頁搜尋。

- 各提供者所預期的用戶端版本會在多次執行之間被記住，因此重新啟動或離線啟動時，不再退回舊的內建值。

- 來自 GLM、Kimi、Qwen、MiniMax、xAI 與其他後端的更多「對話過長」錯誤，現在會觸發壓縮而不是結束該輪；回覆途中發生的 Claude 過載，也遵循與回覆開始時過載相同的重試與備援規則。

- 通知與錯誤不再堆疊在輸入框上方：斜線命令的確認訊息，以及麥克風、附件與命令的失敗都以通知顯示，語音下載進度則只顯示在其「設定」卡片上。所有錯誤現在的呈現方式一致，不再使用框線卡片，本機模型下載則在其列下方顯示全寬進度列。

## v1.0.8 - 2026-10-05

- macOS 應用程式已使用 Developer ID 憑證簽署並通過 Apple 公證，因此下載的副本開啟時不會出現 Gatekeeper 警告，macOS 自動更新也能安裝新版本。麥克風與 AppleScript 的提示現在會說明 Mixdog 使用它們的用途。

## v1.0.7 - 2026-10-04

- 手機上的瀏覽器使用會即時串流桌面頁面，而不是重新整理快照，並與桌面窗格一樣支援滑鼠、觸控、滾輪、鍵盤與 IME 輸入。當代理交出頁面時（例如 CAPTCHA），手機也會開啟該頁面。

- 對話記錄中的工具活動更容易瀏覽：每一列以簡短動詞開頭，讀取與搜尋會顯示逐檔結果，清單顯示檔案列，命令位於各自的方框中，`git diff` 輸出以差異形式呈現，而瀏覽器造訪過的頁面會有一張卡片，可在窗格中重新開啟。

- 回合結束通知送達得更快，顯示純文字而非原始 Markdown，結尾為完整句子，且不再被長時間執行的背景終端機工作延遲。

- 最近使用的工作階段在重新啟動後與再次造訪時開啟得更快。

- setup 工具可以管理 OAuth 帳號、開發人員選項、活動欄的固定項目以及外掛的 MCP 伺服器，也能處理來自分割窗格工作階段的請求。提供者自己的自動清除時間窗現在會覆寫全域設定。

- 只要安裝了 `git`，Git 工具就會啟用，不必安裝擴充功能。排程與 webhook 一律傳送到應用程式工作階段。

- 應用程式介面維持 100% 縮放，在其他視窗或終端機儲存的設定會立即套用，邊框、圖示、清單間距與對話框的進場動畫也更為一致。

## v1.0.6 - 2026-10-03

- 應用程式顯示在畫面上時，手機推播通知會保持安靜，會跟隨瀏覽器自行續期的訂閱，且當系統設定封鎖通知時，開關會自動關閉。

- 手機應用程式在中繼更新後返回時，不再停留在載入畫面；桌面重新連線後便會立即完成載入，而快速的首次啟動也不再略過安裝應用程式的 service worker。

- 在 Android 上，返回手勢會關閉開啟的面板或選單，且導覽列不會閃爍。

- 工作區分頁、側邊面板標題與 Studio 清理按鈕更為精簡，選取的分頁也更為醒目。

- 用量標籤更短；當剩餘不到一天時，重設額度改以每小時計算，且不會超過剩餘量；各語言的翻譯也經過潤飾。

## v1.0.5 - 2026-10-03

- 桌面應用程式可以在一輪以最終答案結束時發出帶有音效的作業系統通知，且通知會帶回該工作階段。

- Office 工具透過同一個共用的瀏覽器工作階段，從 HTML 製作 docx、xlsx 與 pdf 文件。

- 用量顯示配額價值估算與各工作階段的總計。

- 瀏覽器與電腦使用主機更為穩健：畫面轉換、視覺隱私、拼貼截圖，以及失敗後的復原。

- PowerShell 語法檢查不再把路徑中的動詞連字號片段誤認為 cmdlet。

- `adm-zip` 已更新至 0.6.1，以修正 CVE-2026-102282。

## v1.0.4 - 2026-10-01

- 模型選擇器在提供者變更後會立即重新整理。以瀏覽器為基礎的 OAuth 登入（OpenAI、Grok、Cursor、Antigravity）與帳號切換現在會立即重新載入選擇器，不必等到重新啟動；在某個視窗中連線、移除或切換提供者，也會同步重新整理其他所有桌面視窗與已配對的手機。

- 關閉視窗時不再詢問該怎麼做。設定提供「關閉視窗時」的選項，可選擇隱藏到系統匣（預設）或完全結束，系統匣圖示從啟動時就可使用，應用程式內的結束確認提示也已移除。

- 工作流程中的代理列在各處的呈現一致：未固定模型的列（包括網頁搜尋）顯示「預設」，代理名稱與模型標籤維持不翻譯。未選取的工作區分頁改為停留在淡色底板上，而不是細分隔線。

- Goal 工具與 goal-management 技能將目標描述為跨回合執行、已核准工作的任務清單，並排除週期性排程，以及需要等待外部事件數週的目標。

## v1.0.3 - 2026-10-01

- 媒體生成會為每個圖片或影片工作記錄一列用量，內容為提供者回報的權杖、圖片、秒數與費用，因此 Gemini、Antigravity、Codex 與 xAI 的媒體會與文字模型一起出現在用量與費用總計中。媒體費率來自公開的價格目錄。

- 電腦使用的「停止」與「繼續」在清理失敗後能乾淨地復原：閒置的工作程序會被汰除而不是逾時，使用者按下停止或繼續也會清除過期的「input not confirmed released」狀態。

- 等待背景終端機工作的工作階段會顯示為等待中而非閒置，終端機工作指示器也不再顯示前一個擁有者的工作，或遺漏輪詢期間到達的更新。工作階段與代理清單在沒有變化時會略過多餘的重繪。用量圖表、側欄頁面、工作區分頁、擴充功能清單與對話框的樣式都已更新。

- 相同的並行 grep 與 read 掃描會共用同一次原生掃描，編輯後會依路徑使快取結果失效，已取消的修補會在寫入更多檔案之前停止。程式碼圖搜尋比對 Windows 路徑時不分大小寫、分隔符號、逐字（`\\?\`）與 UNC 前綴。失敗的工具前掛鉤現在會阻擋該工具，而不是讓它執行。

- 瀏覽器技能會讓頁面留在背景，除非頁面本身就是交付成果，或使用者必須在上面操作。桌面開發（`npm run dev`）與 Windows 直接 E2E 指令碼會在全新的隔離設定檔中執行，使用 CDP 連接埠 `9342`。

## v1.0.2 - 2026-10-01

- 對話記錄的複製按鈕可以從受信任的桌面視窗寫入剪貼簿。回覆文字、程式碼區塊、工具輸出與各檔案差異，都有針對複製文字是否精確、重試與內容變動的回歸測試；其他視窗對剪貼簿的讀取與權限仍然受到封鎖。

- 模型與強度命令會開啟目前對話的模型選擇器，已停用的代理會保留為其選取的模型。入門教學說明了 Maintainer 模型建議，診斷現在涵蓋本機提供者、內建功能、語音，以及遺失或無效的外掛。

- Windows 檔案連結可處理已編碼的分隔符號，以及含空格或韓文的路徑。初次查詢失敗的檔案提及可以點擊重試。Studio 的「全選」會包含分頁中的每個項目，而不只是已載入的頁面。

- 電腦使用讓擷取參照與無障礙功能重新讀取保持一致，僅在觀察到的身分相符時才安全地重新綁定重建的控制項，並在輸入桌面鎖定時等待，而不是將鎖定視為觀察器失敗。

- 工作區分頁與入門教學的樣式更為清晰，工作階段側邊欄預設展開，工具群組也不再顯示彙總的失敗徽章。專案指示文字不再加入系統提示的環境區塊。發佈的套件排除巢狀的開發測試。

## v1.0.1 - 2026-09-30

- Windows 11 上的桌面應用程式現在採用 Mica 視窗框架，外觀更平靜、單色：彈出視窗與面板以陰影而非邊框區隔，選取項目不再變藍，強調色保留給即時狀態。文字遵循單一字級（從 12px 的說明文字到 20px 的頁面標題與大標數字），選取的分頁是浮起的卡片，破壞性按鈕在游標移上去之前保持中性，用量與情境圖表共用同一組色盤。

- 關閉視窗時會詢問一次要讓 Mixdog 繼續在系統匣中執行還是完全結束，並記住答案。在代理仍在工作時結束，則每次都會詢問。

- 訂閱用量以堆疊面積圖在總計線下方顯示各模型的占比，其浮動卡片只會在圖表內跟隨指標。

- 卡片在捲動期間改變高度時，對話會維持貼附在最新訊息上。代理寫入的 SVG 檔案會以圖片結果顯示，並以系統檢視器開啟；代理會將 SVG 或 HTML 頁面等視覺作品以儲存的檔案交付，而不是貼上原始碼。

## v1.0.0 - 2026-09-30

- 記憶不會再因執行階段重建而失效。重建後的記憶執行階段會以新的發行標籤發佈，而不是取代已安裝應用程式會驗證的檔案；新的執行階段會安裝在使用中的版本旁邊，而不是在 PostgreSQL 仍從中執行時將其刪除；兩個處理程序同時安裝時，也不再互相刪除對方的下載內容。本機開發部署會拒絕從落後上游的分支執行。

- 工具卡片不再把已完成的呼叫標記為失敗。輸出中含有 `status:` 行的命令、回報有差異或無相符項目的 `git diff --quiet` 或 `git grep`、找不到符號的 code_graph 查詢，以及翻閱儲存的 tidy 結果，現在都顯示為已完成；以非零碼結束的 git 命令與終端機一樣顯示為結束碼；因使用者接手控制而停止的瀏覽器或電腦命令則顯示為已取消。

- 網站看到的 瀏覽器使用 是渲染它們的那個 Chrome 版本。User-Agent 字串仍帶有桌面應用程式版本與 Electron 執行階段，而同一批頁面收到的用戶端提示卻只提到 Chromium；GitHub 對這種矛盾的回應是在公開儲存庫上設下登入牆。瀏覽器分割區現在呈現單純的 Chrome 字串——少一個指紋，也少一些「不支援的瀏覽器」繞路——而當任務要求模擬 user agent 時，模擬的仍然優先。

- 持續附加框架的頁面又可以被觀察了。入口網站與新聞首頁會成批開啟廣告版位與小工具，而在批次中途開始的快照過去會以「frame topology changed during observation」放棄——第一次與第二次都能重現。觀察沒有副作用，因此收集器現在會短暫等待批次穩定後再次讀取，直到一個小上限，而不是對一個只是忙碌的頁面回傳錯誤。若讀取仍然失敗，回覆現在會說明頁面已載入，只是讀取失敗，因此下一步是再次觀察，而不是放棄一個沒問題的頁面。

- 頁面只回報它自己的失敗。前一份文件的請求與主控台錯誤留在帳本中，因此正常頁面的快照可能列出先前造訪網站的已中止請求，乾淨頁面上的 `console` 也可能回答前一個頁面的錯誤——兩者都讓讀者去追查並不存在的故障。載入新文件會清除它們；在同一份文件內導覽則會保留，因為沒有重新載入。

- 瀏覽器使用 的顯示競態不再是失敗。擷取輸給導覽或視窗調整大小時，現在回應重新取樣標記而非錯誤，因為窗格本來就會再次索取頁面接下來顯示的內容。一般瀏覽過去會讓應用程式記錄塞滿擷取失敗——一次測試執行中有十七筆，現在為零——而配對的手機把同樣的競態回報為「could not connect to browser screen」；現在它會以作用中的節奏重新取樣，只回報真正停止進展的顯示。

- 清除 瀏覽器使用 瀏覽資料。瀏覽器窗格有一個橡皮擦按鈕，可移除快取、網站儲存在此裝置上的資料以及 cookie，且各自為獨立的決定：快取預先選取，因為失去它只會讓下次重新載入慢一點，而 cookie 會讓您登出每個網站，絕不是預設值。每個範圍各自清除，因此一個失敗會被回報為失敗，而不會消失在成功的範圍後面。清除 cookie 也會改寫在重新啟動之間保存工作階段登入的密封檔案，因此您清除的登入不會在下次開啟應用程式時回來——而若該檔案無法改寫，cookie 會被回報為未清除，而不是已完成。在此之前，共用分割區會在磁碟上不斷成長，卻無法回收。

- 瀏覽器使用 的 `performance` 指標回報的是繪製頁面之處理程序的記憶體，而不只是 JavaScript 堆積：圖片與圖層佔用大量記憶體的頁面，過去看起來很小。該讀數會指出處理程序，因為一個轉譯器可能繪製同一網站的多個頁面。

- 瀏覽器使用 網域政策涵蓋對等連線。當操作者限制頁面可連線的網域時，WebRTC 不再透過 STUN 與 TURN 繞過篩選：頁面與每個子框架中的對等連線都會被拒絕。沒有網域政策時一切不變，而這仍是針對頁面程式碼的圍堵，而不是網路邊界。

- 瀏覽器使用 元素截圖。`snapshot mode=visual` 接受 `ref` 或 `target`，並將該元素作為獨立圖片回傳。方框以頂層文件的 CSS 像素量測——同處理程序框架在頁面端折入其偏移量，跨來源框架加入其工作階段偏移量，但不做保護輸入的點擊測試，因為圖片不會派發任何事件，而處於 CSS 轉換下的框架同樣值得一張圖——裁切則依圖片對視口的比例縮放，因此在縮放或高 DPI 顯示器上也成立。比視窗更高或更寬的元素是從文件擷取而非視口中裁出，因此長表格或文章會完整送達，而不是止於摺疊線；只有大到無法擷取的頁面才會退回可見部分，並會說明。該圖片僅供檢視：絕不會被綁定為座標定位，因為對元素操作的方式仍是 ref。`mode=semantic`、`fullPage` 與 `format=pdf` 會拒絕 target，而不是忽略它。

- 瀏覽器使用 輸入保真度。`drag` 現在能完成頁面自己的 HTML5 拖曳：Chromium 的拖曳攔截交出頁面開始的酬載，手勢以 `dragEnter`/`dragOver`/`drop` 完成，這正是看板卡片、可排序清單或檔案放置區實際監聽的事件；只追蹤滑鼠事件的頁面維持原先的路徑。`type` 為每個字元送出真實的按鍵事件，而不是插入整個字串，因此由按鍵驅動的自動完成與組合方塊會有反應，而美式鍵盤配置以外的字元（韓文、emoji）仍以文字插入。`press` 為標點符號送出美式按鍵碼（`.` 過去是 Delete，`-` 過去是 Insert），避免快速鍵輸入字元，也不再從大寫字母推斷 Shift，這曾使 `Control+A` 變成 `Control+Shift+A`。`upload` 會把檔案放到從不開啟檔案選擇器的元素上，並帶有中和未處理放置的防護——否則瀏覽器會把頁面導覽到被放下的檔案——且在沒有任何元素接受時會清楚回報。

- 瀏覽器使用 觀察保真度。`scroll text=` 像 `read` 與 `expect` 一樣搜尋框架與 shadow root，在其間選出一個相符項，且不再捲動到已收合的元素。`expect.text` 會正規化行內的空格但保留換行，因此縮排的標記可以相符，而兩個獨立區塊也絕不會併成一句。主控台診斷會保留頁面記錄的內容：物件引數以可讀的預覽呈現而不是空訊息，項目會指出讀者會開啟的指令碼與行號，未捕捉的單純 `throw` 也帶有其位置。快照會標記 `aria-hidden`，失敗的原生 `select` 會列出它確實找到的選項，`aria-labelledby` 也能在 shadow root 內解析。

- 瀏覽器使用 會計算它放不下的診斷。頁面報告顯示最新的三筆主控台錯誤與網路失敗，讀起來像是全部：十二個失敗只顯示為三個。報告現在會指出總數，並在清單被截斷時指向 `console` 或 `network`。

- 瀏覽器使用 會承認頁面摘錄提早結束。快照中的可見文字有上限，而報告只說「condensed」，因此長文章讀起來彷彿摘錄就是整個頁面。兩條快照路徑——無障礙擷取與 DOM 後備——現在都會標記被截斷的摘錄，報告會指出它帶有多少內容，並說明頁面還有更多。

- 附件會回報它們實際產生的圖片大小。為符合視覺補丁預算而調整圖片大小，會一次修剪一邊，這可能要求一個圖片填不滿的方框；產生的版本因此比旁邊回報的大小更小，透過該大小對應的座標也就偏了。調整大小現在會回報所產生圖片的尺寸。

- 瀏覽器使用 會指出頁面指令碼在哪裡失敗。`evaluate` 只保留瀏覽器錯誤的第一行，因此多行指令碼回報 `TypeError: ...` 卻無從定位。失敗現在會附帶最內層的堆疊框架，整合測試環境也固定了後面某行的 throw 所回報的位置。

- 瀏覽器使用 會指名 PDF，而不是回報空白頁面。開啟 PDF 的連結會提交網址，但 guest 沒有檢視器，因此快照顯示一個無標題、無文字的頁面，以及關於被封鎖的檢視器樣式表的主控台雜訊——沒有任何內容說明發生了什麼。頁面報告現在會說明該文件是此瀏覽器無法顯示的 PDF，必須從其 URL 讀取檔案；Chromium 自己內建元件為其 `chrome-extension://` 資源引發的失敗，也不再顯示為頁面的主控台或網路錯誤。整合測試環境涵蓋了導覽、安靜的報告，以及之後對該頁面的快照。

- 瀏覽器使用 不再讓 `close_tab` 在可見分頁上碰壁。`list_tabs` 以一般頁面 id 列印可見頁面，因此把 `close_tab` 指向它時，得到的是 `unknown background tab "p12"; call list_tabs`——也就是交出這個 id 的那份清單。拒絕訊息現在會說明該頁面屬於瀏覽器面板，並指向將其導覽至他處或 `hide`，而無關的名稱仍會回報未知的背景分頁。

- 瀏覽器使用 會說明離開確認實際做了什麼。保護未儲存工作的頁面以 `beforeunload` 對話框擋下導覽，而回覆要求使用 `handle_dialog`——但 Chromium 會自行回應該確認，因此該呼叫總是回傳「no JavaScript dialog is currently open」，重複導覽也只是重複同一個指示。回覆現在會說明導覽已被放棄、頁面留在原處、已沒有可回應的內容，以及頁面中的工作必須先完成或捨棄；整合測試環境涵蓋整個序列，包括防護消失後導覽順利通過。

- 瀏覽器使用 的地區設定模擬會到達伺服器。`emulate locale` 過去只設定 `navigator.language`，因此頁面仍請求舊語言，網站協商出與模擬相矛盾的內容；現在它也將該地區設定作為 `Accept-Language` 帶出，清除後會還原瀏覽器本身的協商。

- 瀏覽器使用 把兩個手勢併入相鄰的手勢。核取方塊或選項按鈕改由帶有 `checked` 而非 `text` 的 `fill` 設定——無論是單一控制項、`fields` 項目或 `sequence` 步驟——因此獨立的 `check` 動作已移除；`forward` 也移除了，因為先前的快照已顯示要 `navigate` 的 URL，而 `back` 仍是一個手勢。`locate` 與 `extract` 保留：前者是沒有語意對應的視覺（像素）搜尋，後者則讀取跨框架與開啟的 shadow root 的列，這是 `evaluate` 無法觸及的。

- 電腦使用的 `capture` 移除了 `quality`、`maxWidth` 與 `max_ocr_words` 旋鈕：改採主機調校過的預設值（JPEG 品質、縮小寬度，以及元素預算已限制的 OCR 字數上限），看不清的細節以 `zoom` 處理，而不是重新編碼。元素篩選器（`query`、`role`、`visible_only`、`include_noninteractive`、`continuation`）與 `window` 移動幾何現在會說明它們的作用，而不是未加說明地掛在結構描述上。

- 瀏覽器使用 與電腦使用在模型做決定之處，陳述它們在工具階梯上的位置。`browser` 描述以「last resort: prefer web_fetch, an MCP tool, or a CLI in shell」開頭，`computer` 以「last resort after an MCP tool, shell/CLI, and 瀏覽器使用; never a stand-in for a page action browser refused」開頭，共用規則與兩個技能也帶有相同的階梯，因此有 API 或 CLI 的服務會透過它們存取，而不是透過螢幕。兩個描述都沒有變長：階梯取代了技能本來就擁有的措辭。

- 瀏覽器使用 現為兩個工具。`browser` 保留日常頁面工作——navigate、snapshot、read、click、fill、表單、對話框、分頁、下載、console 與 network 讀取——而開發人員控制項 `emulate`、`cookies`、`storage`、`intercept`、`init_script` 與 `performance` 移到延後載入的 `browser_devtools` 工具，它驅動相同的頁面與登入，並在第一次呼叫時載入其結構描述。日常結構描述移除了僅這些動作使用的 33 個欄位（cookie 屬性、地理位置、CPU 節流、攔截本文、追蹤選項），每個工具的欄位註記只列出自己的動作，而呼叫到錯誤工具的呼叫會被拒絕，並指出應呼叫的工具。主機、其動作登錄表、核准政策與整合測試環境仍維持單一共用的動作契約。

- 內建工具結構描述只陳述契約。`office`、`computer`、`media` 與 `setup` 的工具描述與欄位註記刪去其技能本來就擁有的方法與政策句子——批次處理、何時 snapshot 或 `describe`、在同一回合修正稽核、`design.content` 重用、巨集處理、不要重新排列、螢幕內容絕不授權動作、影片輪詢、刪除核准程序——這從每回合都會傳送的工具介面中移除約 2.2 KB（office −878 B、computer −492 B、media −432 B、setup −424 B）。pptx、xlsx 與 pdf 技能現在帶有原本只存在於結構描述中的規則（一批已知的操作、僅對未知欄位使用 `describe`、不受信任的文件內容），而 computer-use 技能則將呼叫契約陳述一次，而不是重複每一句結構描述的句子。

- 瀏覽器使用 每項任務所需的呼叫更少。`click`、`fill`、`type`、`select`、`hover`、`upload` 與 `scroll`——以及每個 `fill.fields` 項目與 `sequence` 步驟——都接受免快照的 `target`（`{role, name}`、`{name}` 或 `{selector}`）來取代 `ref`：主機自己觀察頁面，只對恰好一個相符項動作（多個子字串相符時會解析為唯一完整相符的那個），而模稜兩可的目標會失敗並附上候選項及其最新的 ref。`snapshot`、`read` 與 `wait` 上的 `query` 以 OR 比對以空格分隔的關鍵字（全部關鍵字都符合者排在前面），並接受 `/pattern/i` 正規表示式；沒有任何相符的篩選器會說明它篩選了多少元素或字元。透明或 pointer-events:none 的控制項不再被直接拒絕：隱藏的核取方塊會透過其標籤點擊，輸入目標防護也接受標籤的啟動。對 `contenteditable` 編輯器執行 `fill` 時，會以全選後輸入的方式取代內容，而不是覆寫其 DOM。當手勢沒有動到文件、URL 與控制項值時，回覆會註明「No observable change」；`brief:true` 只列出自上次觀察以來新增或變更的元素；主控台錯誤在新出現時只回報一次；已經成立的後置條件是警告而非錯誤。快照以 `file-input`、`accept=…` 與 `multiple` 標記檔案輸入；完整頁面截圖在擷取時將 fixed 與 sticky 元素固定在流程中；工作階段 cookie 以作業系統金鑰鏈加密儲存並在啟動時還原，因此登入狀態可在應用程式重新啟動後保留。

- 提示輸入框上方的介面——Goal 膠囊、執行階段進度、工具核准、草稿情境列與回合審閱位置——現在集中於一個 `ComposerDock`，當這些介面解析完畢時，對話記錄也不再上下晃動：在某個範圍的第一次權威 worker 讀取進行中時，審閱位置會保持保留，因此在對話記錄顯示之後才到達的差異，會填入既有的幾何空間，而不是再次調整視口大小。釋出的空間絕不以計時器保留。桌面主機也不再於每次接受提示後重新讀取整個工作階段（常駐程式記錄的「missing baseline」復原）：重複投影已持有修訂版的回覆或車道框架，是已套用的狀態，而不是交錯的基準。Goal 膠囊的掛載/卸載切換可在 `MIXDOG_DESKTOP_PERF=1` 下追溯。
