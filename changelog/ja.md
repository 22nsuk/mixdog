# 変更履歴

主な変更点を新しい順に掲載しています。Deploy パイプラインは、Unreleased セクションが空の間はリリースを行わず、
リリース時にそのセクションへリリースしたバージョンを記載します。

## Unreleased

- 「設定」>「情報」の変更履歴に、インストール済みバージョンのリリースノートが表示されるようになりました。
  v1.0.11 では v1.0.10 までで途切れていました。デスクトップアプリでもリモートのウェブページでも同様です。

- 変更履歴はすべてのアプリの言語で利用でき、アップデート後には、そのバージョンの新機能が一度だけ表示されます。

- 自動推論は、対応モデルで既定で有効になります。各メッセージと各ツールのステップに必要な推論の強度が適用されます。
  そのモデルは、起動時ではなく初回の使用時にバックグラウンドでダウンロードされ、
  「組み込み」カードにはモデルとその基になったモデルが表示されます。

- 会話内のファイルリンクは、会話の横にあるサイドパネルのタブで開きます。
  新しいリンクはプレビュータブを置き換えるため、リンクを開くたびにタブが増えることはありません。
  タブは、ダブルクリックするか、「常に開く」を選ぶか、ファイルを編集すると保持されます。
  ファイルのタブは最大 8 つまで開いたままにできます。「設定」>「一般」>「リンクのプレビュー」でこの動作をオフにできます。

- CSV ファイルと TSV ファイルは、編集可能な表として開きます。セルのコピーと貼り付け、行や列の追加と削除、
  Ctrl+S での保存、Ctrl+Z と Ctrl+Y での元に戻す/やり直しができます。

- PDF と Office ファイル (Word、PowerPoint、Excel) をサイドパネルでプレビューできます。
  Office のページはすぐに開き直せ、リンクにポインターを合わせた時点でドキュメントの変換が始まります。

- 会話にスターを付けられます。お気に入りはセッション一覧の先頭に表示され、行にカーソルを合わせるとスターが現れます。

- 検索は、過去の会話をまたいでテキストを見つけます。削除された会話は、どの方法で削除されても検索結果に残りません。

- 返信のストリーミング中に上へスクロールしても、位置が保たれ、末尾へ戻されることはありません。

- 返信内の GitHub のアクションは 1 つの GitHub カードにまとめられ、思考インジケーターのループは、再開時に飛ぶことがなくなりました。

- プロバイダーのアカウントにはサインインに使ったメールアドレスが表示され、同じアカウントを再度接続しても、
  新しい項目が追加されず、名前と使用履歴が保持されます。使用量ダイアログには、接続解除済みのアカウントが表示されなくなりました。

- キューからドラフトに戻したプロンプトは、再起動後に再び現れなくなり、アプリをすぐに開き直しても、
  会話が読み取り専用で開くことなく編集可能なままになります。

- 翻訳の修正: イタリア語の Git、ベトナム語の Models、中国語と日本語の Effort など、誤っていたラベルが正しく表示されるようになりました。

- スマートフォンのウェブ UI では、Enter で改行が挿入され、送信ボタンで送信されます。

- ユーザーフォルダー名が ASCII だけではない Windows プロファイルでも、メモリが起動するようになりました。

- image-size と js-yaml の依存関係のセキュリティアップデート
  (CVE-2025-71329、CVE-2026-84375)。

## v1.0.11 - 2026-10-08

- 表示スケールが 100% を超える Windows ディスプレイでも、内蔵ブラウザーがページを正しく表示するようになりました。
  これまでは「Browser display did not recover after the page changed」というエラーで失敗していました (#8)。
  ページは表示スケールの変更にも追従し、その時点で画面に表示されていなかったタブも対象です。

- Word、PowerPoint、Excel のファイル (.docx、.pptx、.xlsx、.xlsm) をメッセージや自動化に添付でき、
  その内容のテキストはすべてのモデルに届きます。添付できない形式のファイルはその旨が表示され、
  代わりにファイルパスが挿入されます。空のファイルや本物の PDF ではないファイルは、分かりやすいメッセージとともに拒否されます。

- 会話内で以前に添付された PDF や画像は、アプリを再起動した後もモデルに送信されます。
  PDF をネイティブに扱えないモデルには、PDF のテキストが渡されます。100 ページを超える PDF を読み取ると、
  冒頭の数ページがテキストとして返されます。パスワード付きの PDF や無効な PDF は、
  以降のリクエストを壊す代わりに、分かりやすいエラーを返します。

- MCP ツールが返す画像やファイルは、エンコードされた生のテキストではなく、画像やファイルとしてモデルに届きます。
  未対応またはサイズ超過のメディアは、その内容が説明として渡されます。

- 長い会話を圧縮したときに作られる要約に、長いメッセージが含まれるようになり、添付された画像やファイルも記載されます。

- テキスト専用のローカルモデルでも、添付ドキュメントのテキストが保持されます。以前の画像は、
  会話が止まる代わりに短い注記に置き換えられます。

- 「設定」>「情報」から、スクリーンショット (任意) 付きのフィードバックを送信でき、変更履歴もそこで読めます。

- 直近の会話メッセージは、保存された直後からメモリの想起で意味によって検索できます。

- 検索結果は、まだ新しい間だけ再利用されます (#7)。また、内容検索の後にファイル一覧検索を行うと、
  以前の内容ではなくファイル名が返されます (#9)。

## v1.0.10 - 2026-10-08

- カスタム API プロバイダーを「設定」で登録でき、プロバイダー固有の接続アダプターを使用できます。

- リモート接続の QR コードは、リレーの準備ができてから表示され、古いペアリングカードは消去されます。

- OpenRouter のローリングモデルエイリアスを選択し、Main とエージェントに保存できます。
  最新のエイリアスや安定版モデルが、カタログの古さ、新しいプレビュー版、モデルピッカーのファミリー制限によって誤って非表示になることはなくなりました。

- ネイティブパッチの初期化は、検証が保留中の間もプロセスを維持します。プリウォームと検証が重なったときの早期終了を防ぎます。

## v1.0.9 - 2026-10-07

- 共通の指示とプロジェクトの指示は、メモリ拡張機能がインストールされていない場合やオフの場合でも、
  すべての新しい会話に届きます。このスイッチが対象とするのは、メモリツールと想起ツールのみになりました。
  指示を保存するときに、埋め込みモデルのために数秒待たされることはなくなり、指示は内部 ID なしで書いたとおりに渡され、
  合計で最大 32 KB まで設定できます。

- 「設定」からの GitHub サインインや、ターミナルプロセスを起動するその他すべての機能が、
  インストール済みのデスクトップアプリで再び動作します。以前は「posix_spawnp failed」で失敗していました。
  gh に保存された古い余分な GitHub アカウントが原因で、サインインに成功しても「no account is signed in」と表示される問題も解消されました。

- ブラウザユースとコンピュータユースは、セッション内の最初の呼び出しの前に承認を求めなくなりました。
  `setup set_first_use_approval` は廃止されました。

- ツール承認カードが、入力欄の上に積み重なる他のカードと同じ見た目になりました。警告アイコン、タイトル、ツールが 1 行に並び、
  その下に理由が表示されます。承認対象のコマンド、パス、URL のみが表示され (フォルダー行や引数の一覧はありません)、
  「拒否」は「許可」の横に控えめに配置されます。

- 新しいモデルの機能は、リリースを待たずにプロバイダーのカタログから反映されます。ChatGPT ルートでの会話中の努力レベル変更、
  OpenAI API ルートでの Fast モードとキャッシュ設定、Claude での Fast モード、xAI での推論の努力レベルが対象です。
  GPT-6.1 Sol と Claude Sonnet 5.5 にも対応しました。Fast を使えない Claude モデルには、Fast の切り替えが表示されなくなりました。

- Claude Sonnet 5.5 が、ツール呼び出しの合間のメモを再び表示するようになりました。Claude Fable と Mythos のモデルは、ホスト型のウェブ検索を使えます。

- 各プロバイダーが要求するクライアントバージョンが実行間で記憶されるため、再起動やオフラインでの起動で古い組み込みの値に戻ることはなくなりました。

- GLM、Kimi、Qwen、MiniMax、xAI などのバックエンドが返す「conversation too long」系のエラーがより多く検出され、
  ターンを終了せずに圧縮が実行されるようになりました。返信の途中で発生した Claude の過負荷も、返信の開始時と同じ再試行・フォールバックのルールに従います。

- 通知やエラーが入力欄の上に積み重ならなくなりました。スラッシュコマンドの確認や、マイク、添付、コマンドの失敗は通知として表示され、
  音声ダウンロードの進行状況は「設定」のカード上にのみ表示されます。すべてのエラーが枠付きカードなしの同じ表記になり、
  ローカルモデルのダウンロードでは、各行の下に全幅の進行状況バーが表示されます。

## v1.0.8 - 2026-10-05

- macOS アプリは Developer ID 証明書で署名され、Apple による公証を受けています。ダウンロードしたアプリは Gatekeeper の警告なしで開け、
  macOS の自動アップデートで新しいバージョンをインストールできます。マイクと AppleScript の許可ダイアログでは、
  Mixdog が何のために使用するのかが説明されるようになりました。

## v1.0.7 - 2026-10-04

- スマートフォンのブラウザユースは、スナップショットを更新する代わりにデスクトップのページをライブでストリーミングし、
  デスクトップのペインと同じマウス、タッチ、ホイール、キーボード、IME の入力を受け付けます。
  エージェントがページを引き渡したとき (CAPTCHA など) は、スマートフォン側でもそのページが開きます。

- トランスクリプトでのツールの動作が見やすくなりました。各行は短い動詞で始まり、読み取りと検索ではファイルごとの結果が表示され、
  一覧ではファイル行が表示されます。コマンドは専用のボックスに収まり、`git diff` の出力は差分として描画され、
  ブラウザーが訪問したページには、ペインで開き直せるカードが表示されます。

- ターン完了の通知が、より早く届くようになりました。生の Markdown ではなくプレーンテキストで表示され、
  文の区切りで終わり、長時間実行中のバックグラウンドシェルジョブに通知を止められることもなくなりました。

- 最近使ったセッションは、再起動後や再度開いたときに、より速く開きます。

- setup ツールで、OAuth アカウント、開発者オプション、アクティビティレールのピン、プラグインの MCP サーバーを管理できるようになり、
  分割ペインのセッションからのリクエストにも対応しました。プロバイダー固有の自動クリア期間が、グローバルな設定より優先されます。

- Git ツールは、`git` がインストールされている環境であれば、拡張機能をインストールしなくても有効になります。
  スケジュールと Webhook は、常にアプリのセッションへ配信されます。

- アプリのインターフェースは常に 100% のスケールで表示されます。別のウィンドウやターミナルで保存した設定は、すぐに反映されます。
  また、枠線、アイコン、リストの間隔、ダイアログの表示アニメーションがより統一されました。

- PowerShell の構文チェックが、パス内の「動詞-ハイフン」形式の断片を cmdlet と誤認しなくなりました。

- `adm-zip` を 0.6.1 に更新しました (CVE-2026-102282 への対応)。

## v1.0.4 - 2026-10-01

- モデルピッカーは、プロバイダーが変更されるとすぐに更新されます。ブラウザーベースの OAuth サインイン (OpenAI、Grok、Cursor、Antigravity) やアカウントの切り替え後、
  再起動を待たずにピッカーが再読み込みされます。また、あるウィンドウでプロバイダーを接続・削除・切り替えると、他のすべてのデスクトップウィンドウとペアリング済みのスマートフォンも更新されます。

- ウィンドウを閉じるときに、どうするかを尋ねなくなりました。設定に「ウィンドウを閉じたとき」の選択肢が追加され、トレイに隠す (既定) か完全に終了するかを選べます。
  トレイアイコンは起動時から利用でき、アプリ内の終了確認プロンプトは廃止されました。

- ワークフローのエージェント行の表記が、どこでも統一されました。モデルを固定していない行 (ウェブ検索を含む) は「既定」と表示され、
  エージェント名とモデルのラベルは翻訳されません。選択されていないワークスペースのタブは、細い区切り線ではなく淡いプレートの上に表示されます。

- 目標ツールと goal-management スキルは、目標を「承認済みの作業をターンをまたいで進めるためのタスクリスト」と説明するようになり、
  定期的なスケジュールや、外部の出来事を数週間待つ目標は対象外としています。

## v1.0.3 - 2026-10-01

- メディア生成は、画像または動画のジョブごとに 1 行の使用量を記録します。プロバイダーが報告したトークン、画像、秒数、コストが含まれるため、
  Gemini、Antigravity、Codex、xAI のメディアが、テキストモデルと並んで使用量とコストの合計に表示されます。メディアの料金は、公開されている価格カタログに基づきます。

- コンピュータユースの停止と再開が、クリーンアップ失敗後も正常に復旧するようになりました。アイドル状態のワーカーはタイムアウトを待たずに破棄され、
  ユーザーが停止または再開を行うと、古い「input not confirmed released」状態が解除されます。

- バックグラウンドのシェルジョブを待っているセッションは、アイドルではなく待機中として表示されます。シェルジョブのインジケーターは、以前の所有者のジョブを表示したり、
  ポーリング中に届いた更新を取りこぼしたりしなくなりました。セッションとエージェントの一覧は、変更がないときの不要な再描画を省略します。
  使用量チャート、レールページ、ワークスペースのタブ、拡張機能の一覧、ダイアログのスタイルも刷新されました。

- 同時に実行される同一の grep と read のスキャンは、1 回のネイティブスキャンを共有します。キャッシュされた結果は、編集後にパスごとに無効化され、
  キャンセルされたパッチは、それ以降のファイルの書き込みを行わずに停止します。コードグラフ検索は、Windows パスを大文字小文字、区切り文字、
  verbatim (`\\?\`) や UNC のプレフィックスに関係なく照合します。失敗した pre-tool フックは、ツールを実行させずにブロックするようになりました。

- ブラウザースキルは、ページ自体が成果物である場合やユーザーが操作する必要がある場合を除き、ページをバックグラウンドで保持します。
  デスクトップ開発 (`npm run dev`) と Windows 直接 E2E スクリプトは、CDP ポート `9342` の新しい分離プロファイルで実行されます。

## v1.0.2 - 2026-10-01

- トランスクリプトのコピーボタンは、信頼されたデスクトップウィンドウからクリップボードへ書き込めます。応答テキスト、コードブロック、ツール出力、ファイルごとの差分については、
  コピーされるテキストの正確さ、再試行、内容の変化に対するリグレッションテストが追加されました。他のウィンドウからのクリップボードの読み取りと権限は、引き続きブロックされます。

- モデルと努力のコマンドは、現在の会話のモデルピッカーを開きます。無効なエージェントも、選択されたモデルを保持します。スターターチュートリアルでは Maintainer のモデル推奨が説明され、
  診断の対象に、ローカルプロバイダー、組み込み機能、音声、存在しない・無効なプラグインが加わりました。

- Windows のファイルリンクが、エンコードされた区切り文字や、スペースや韓国語を含むパスを扱えるようになりました。最初の検索に失敗したファイルメンションは、クリックして再試行できます。
  Studio の「すべて選択」は、読み込み済みのページだけでなく、タブ内のすべての項目を対象にします。

- コンピュータユースは、キャプチャ参照をアクセシビリティの再読み取りと整合させ、再構築されたコントロールを、観測された ID が一致する場合にのみ安全に再バインドします。
  入力デスクトップがロックされている間は、ロックをオブザーバーの障害として扱わずに待機します。

- ワークスペースのタブとスターターチュートリアルのスタイルがより分かりやすくなり、セッションサイドバーは開いた状態で始まり、ツールグループに集計の失敗バッジが表示されなくなりました。
  プロジェクトの指示テキストは、システムプロンプトの環境ブロックに追加されなくなりました。公開パッケージからは、入れ子になった開発用テストが除外されます。

## v1.0.1 - 2026-09-30

- Windows 11 のデスクトップアプリが、Mica ウィンドウフレームに収まり、より落ち着いたモノクロのシェルになりました。ポップアップとパネルは枠線ではなく影で区切られ、
  選択しても青くならず、アクセントカラーはライブ状態のために残されています。テキストは 1 つのタイプスケール (12px のキャプションから 20px のページタイトルと見出しの数値まで) に従い、

- `drag` は、他のすべてのポインター操作と同様に、スナップショット不要のターゲットを受け付けます。2 つの端は ref または生の座標しか受け付けず、カード、リスト行、ドロップゾーンなど、
  ページがドラッグ可能にする要素にはアクセシブルな名前がなく、したがって ref もないことが多いため、CSS セレクターが分かっていても、先にビジュアルスナップショットでグラウンディングする必要がありました。
  `target` と `dropTarget` で 2 つの端を指定し、1 回の観測でまとめて解決されます。ref と座標はこれまでどおり使え、両端は引き続き同じ方法で指定する必要があります。

- 保存されたファイルが、失敗したリクエストとして通知されなくなりました。ダウンロードに変わるアドレスは自身のナビゲーションをキャンセルし、Chromium はそのキャンセルを `net::ERR_ABORTED` として報告するため、
  ダウンロードを一覧に載せる返信が、最近のネットワーク障害としても載せていました。キャンセルされたリクエスト (ダウンロード、ページが放棄した fetch、別のナビゲーションに置き換えられたナビゲーション) は、
  `network` から引き続き読めますが、ページの障害として自発的に通知されなくなりました。本当に失敗したリクエストは、これまでどおり通知されます。

- `brief` の返信が、1 つの入力済みフィールドをページ全体の変更として扱わなくなりました。返信は呼び出し元の前回の観測と比較しますが、その観測が上限で切られていたりフィルターされていたりした場合は、
  ページの残りを一度も報告していなかったため、その外側のすべての要素が「changed or new」として列挙されていました。フォームの 3 つのボックスに入力すると 15 個の要素で返信され、
  検索語を 1 語入力すると 146 個で返信されていました。返信は、操作が確かに変更したものと、以前の観測が単に対象としていなかったものを分けて示し、その観測がページのどれだけを保持していたかも伝えます。
  いずれの場合も、省略されるものはありません。

- `network` のリクエストヘッダーは、実際に送信されたものになります。Chromium はまず暫定のセットを報告し、その後に言語、エンコーディング、クライアントヒント、Cookie を追加するため、
  リクエストの詳細に 2 つのヘッダーしか表示されず、ページが韓国語のコンテンツを一度も要求しなかったかのように読めることがありました。後のセットがマージされ、
  認証情報は引き続き名前のみが示され、表示されることはありません。ヘッダー名は大文字小文字を区別せず、2 つの報告で綴りが異なるため、マージでは、実際にネットワークに流れた綴りと値でヘッダーごとに 1 エントリを保持し、
  `User-Agent` と `user-agent` の両方をリクエストが持っているかのように列挙することはなくなりました。

- サイトからは、ブラウザユースが、そのサイトを描画する Chrome ビルドとして見えるようになりました。ユーザーエージェント文字列にはデスクトップアプリのバージョンと Electron ランタイムが残っていた一方、
  同じページが受け取るクライアントヒントは Chromium のみを示していました。GitHub はこの矛盾に対して、公開リポジトリでもサインインを要求していました。
  ブラウザーパーティションはプレーンな Chrome 文字列を提示します。フィンガープリントが 1 つ減り、「未対応のブラウザー」への遠回りも減ります。タスクが要求した場合は、エミュレートされたユーザーエージェントが引き続き優先されます。

- フレームを次々とアタッチし続けるページを、再び観測できるようになりました。ポータルやニュースのトップページは、広告スロットやウィジェットを一斉に開くため、その最中に開始したスナップショットは、
  「frame topology changed during observation」で、1 回目も 2 回目も再現的に諦めていました。観測には副作用がないため、コレクターは、ビジー状態だっただけのページに対してエラーを返す代わりに、
  一斉の処理が落ち着くまで短時間待機して、上限の小さな回数まで再読み取りします。それでも読み取りに失敗した場合、返信は、ページは読み込まれており、失敗したのはその読み取りだけだと伝えるため、
  問題のないページを諦めるのではなく、もう一度観測するのが次の手順になります。

- ページは、自身の失敗のみを報告します。前のドキュメントのリクエストとコンソールエラーが台帳に残っていたため、正常なページのスナップショットが、その前に訪れたサイトの中断されたリクエストを列挙したり、
  クリーンなページの `console` が前のページのエラーで応答したりしていました。どちらも、存在しない障害を探させるものでした。新しいドキュメントを読み込むとこれらは消去されます。
  同一ドキュメント内のナビゲーションでは、何も再読み込みされないため、保持されます。

- ブラウザユースの表示の競合が、障害ではなくなりました。ナビゲーションやウィンドウのリサイズに負けたキャプチャは、エラーではなく再サンプリングのマーカーで応答します。
  ペインは、ページが次に表示するものを必ずもう一度要求するからです。通常のブラウジングで、アプリのログがキャプチャの失敗で埋まっていました (ハーネスの 1 回の実行で 17 件、現在は 0 件)。
  ペアリングされたスマートフォンは、同じ競合を「could not connect to browser screen」と報告していましたが、現在はアクティブな間隔で再サンプリングし、表示が本当に進行しなくなった場合のみ報告します。

- ブラウザユースの閲覧データを消去できます。ブラウザーペインには消しゴムボタンがあり、キャッシュ、このデバイスにサイトが保存したデータ、Cookie を、それぞれ個別の選択として削除します。
  キャッシュは失っても再読み込みが 1 回遅くなるだけなので最初から選択されていますが、Cookie はすべてのサイトからサインアウトされるため、既定にはなりません。
  各範囲は個別に消去されるため、1 つの失敗は、成功した範囲に隠れることなく失敗として報告されます。Cookie を消去すると、再起動をまたいでセッションのサインインを保持する暗号化ファイルも書き換えられるため、
  消去したログインが次回アプリを開いたときに戻ってくることはありません。そのファイルを書き換えられなかった場合、Cookie は完了ではなく、消去されなかったと報告されます。
  これまで、共有パーティションはディスク上で増え続け、回収する手段がありませんでした。

- ブラウザユースの `performance` メトリクスは、JavaScript ヒープだけでなく、ページを描画するプロセスのメモリを報告します。画像やレイヤーがメモリを保持しているページは、以前は小さく見えていました。
  1 つのレンダラーが同じサイトの複数のページを描画することがあるため、読み取り値にはプロセスが明示されます。

- ブラウザユースのドメインポリシーが、ピア接続も対象にします。オペレーターがページの到達できるドメインを制限した場合、WebRTC が STUN と TURN を通じてフィルターをすり抜けることはなくなり、
  ピア接続はページ内とすべての子フレームで拒否されます。ドメインポリシーがなければ何も変わらず、これはネットワーク境界ではなく、ページのコードに対する封じ込めであることに変わりありません。

- ブラウザユースの要素スクリーンショット。`snapshot mode=visual` が `ref` または `target` を受け付け、その要素を単独の画像として返します。ボックスはトップドキュメントの CSS ピクセルで計測されます。
  同一プロセスのフレームはページ側でオフセットを折り込み、クロスオリジンのフレームは、入力を保護するヒットテストなしでセッションオフセットを加えます。画像は何もディスパッチしませんが、
  CSS 変換下のフレームにも相応の画像が必要だからです。切り抜きは、画像とビューポートの比率でスケールされるため、拡大表示や高 DPI ディスプレイでも正しく機能します。
  ウィンドウより高い、または広い要素は、ビューポートではなくドキュメントのキャプチャから切り出されるため、長い表や記事も、折り返し位置で終わらず全体が届きます。
  キャプチャするには大きすぎるページのみが、見えている部分にフォールバックし、その旨が示されます。画像は検査専用で、座標のグラウンディングとして関連付けられることはありません。要素を操作する手段は引き続き ref だからです。
  `mode=semantic`、`fullPage`、`format=pdf` は、ターゲットを無視せず、拒否します。

- ブラウザユースの入力の忠実度。`drag` が、ページ自身の HTML5 ドラッグを完了できるようになりました。Chromium のドラッグインターセプトが、ページが開始したペイロードを引き渡し、
  ジェスチャーは `dragEnter`/`dragOver`/`drop` として完了します。これは、かんばんカード、並べ替え可能なリスト、ファイルドロップゾーンが実際にリッスンしているものです。
  マウスイベントだけを追跡するページは、従来の経路のままです。`type` は文字列全体を挿入する代わりに、1 文字ごとに本物のキーイベントを送るため、キー入力で動作するオートコンプリートやコンボボックスが反応します。
  US 配列にない文字 (韓国語、絵文字) は、引き続きテキストとして挿入されます。`press` は句読点に US のキーコードを送り (以前は `.` が Delete、`-` が Insert でした)、ショートカットが文字を入力しないようにし、
  大文字から Shift を推測しなくなりました (`Control+A` が `Control+Shift+A` になっていました)。`upload` は、ファイル選択を開かない要素にファイルをドロップし、未処理のドロップを無効化するガードを備えています
  (そうしないと、ブラウザーがページをドロップされたファイルへ移動させてしまいます)。何も受け付けなかった場合は、その旨をはっきり報告します。

- ブラウザユースの観測の忠実度。`scroll text=` は、`read` や `expect` と同様にフレームとシャドウルートを検索し、それらをまたいで 1 つの一致を選び、折りたたまれた要素にはスクロールしなくなりました。
  `expect.text` は行内のスペースを正規化しますが、改行は保持するため、インデントされたマークアップは一致し、別々の 2 つのブロックが 1 つの文に結合されることはありません。
  コンソール診断は、ページがログに記録した内容を保持します。オブジェクト引数は空のメッセージではなく読みやすいプレビューとして届き、エントリは読み手が開くスクリプトと行を示し、
  キャッチされない裸の `throw` は位置情報を伴います。スナップショットは `aria-hidden` を示し、失敗したネイティブ `select` は見つかった選択肢を列挙し、`aria-labelledby` はシャドウルート内で解決されます。

- ブラウザユースは、収まりきらなかった診断の数を数えます。ページレポートは、最新のコンソールエラーとネットワーク障害を 3 件ずつ表示するため、それが全体のように読めました。
  12 件の障害が 3 件として届いていたのです。レポートは合計を示し、リストが上限で切られている場合は常に `console` または `network` を案内します。

- ブラウザユースは、ページの抜粋が途中で終わっていることを明示します。スナップショットの可視テキストには上限があり、レポートは「condensed」とだけ示していたため、長い記事では抜粋がページ全体のように読めました。
  アクセシビリティキャプチャと DOM フォールバックの両方の経路で、切り詰められた抜粋に印が付き、レポートは含まれる量と、ページにはさらに内容があることを示します。

- 添付ファイルは、実際に生成された画像のサイズを報告します。画像をビジョンパッチの予算に合わせると、端が 1 つずつ削られ、画像が埋めないボックスを要求することがあります。
  その結果、変換後の画像が横に報告されたサイズより小さくなり、そのサイズを通じてマッピングされた座標がずれていました。リサイズは、生成された画像の寸法を報告するようになりました。

- ブラウザユースは、ページのスクリプトが失敗した場所を示します。`evaluate` はブラウザーのエラーの最初の行しか保持しなかったため、複数行のスクリプトは `TypeError: ...` とだけ報告し、場所を特定する手がかりがありませんでした。
  失敗には最も内側のスタックフレームが付くようになり、統合ハーネスは、後の行で throw した場合に報告される位置を固定して検証します。

- ブラウザユースは、PDF を空のページとして報告する代わりに、PDF であることを示します。PDF へのリンクを開くとアドレスは確定しますが、ゲストにはそのビューアーがないため、スナップショットはタイトルもテキストもないページで、
  ブロックされたビューアーのスタイルシートに関するコンソールのノイズだけが表示され、何が起きたのかが分かりませんでした。ページレポートは、そのドキュメントがこのブラウザーでは表示できない PDF であり、
  ファイルは URL から読む必要があることを示すようになりました。Chromium 自身の同梱コンポーネントが `chrome-extension://` リソースに対して発生させる失敗は、ページのコンソールエラーやネットワークエラーとして表示されなくなりました。
  統合ハーネスは、ナビゲーション、静かなレポート、そのページの後続のスナップショットを対象にしています。

- ブラウザユースは、`close_tab` を表示中のタブに対して拒否し続けるのをやめました。`list_tabs` は表示中のページを通常のページ ID で出力するため、それを `close_tab` の対象にすると、
  そのIDを渡した一覧そのものに対して `unknown background tab "p12"; call list_tabs` と応答していました。拒否メッセージは、そのページがブラウザーパネルに属することを示し、別の場所へ移動するか `hide` を使うよう案内します。
  無関係な名前は、引き続き不明なバックグラウンドタブとして報告されます。

- ブラウザユースは、離脱の確認が実際に何をしたかを伝えます。未保存の作業を守るページが `beforeunload` ダイアログでナビゲーションを止め、返信は `handle_dialog` を求めていましたが、
  Chromium はその確認に自分で応答するため、呼び出しは常に「no JavaScript dialog is currently open」を返し、ナビゲーションを繰り返しても同じ指示が繰り返されていました。
  返信は、ナビゲーションが中止されてページがそのまま残ったこと、応答すべきものは何も残っていないこと、ページが保持している作業を先に完了するか破棄する必要があることを示します。
  統合ハーネスは、ガードがなくなった後にナビゲーションが通ることも含め、一連の流れ全体を検証します。

- ブラウザユースのロケールのエミュレーションが、サーバーにも届くようになりました。`emulate locale` は `navigator.language` だけを設定していたため、ページは古い言語を要求し続け、
  サイトはエミュレーションと矛盾するコンテンツをネゴシエートしていました。現在はロケールを `Accept-Language` としても送信し、解除するとブラウザー本来のネゴシエーションに戻ります。
